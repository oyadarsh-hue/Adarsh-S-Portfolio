SYSTEM CONCEPT / QUIETNOTE

01 / CONTEXT

The problem

A one-time link can be opened twice if concurrent requests check its availability before either marks it as consumed.

02 / RESPONSE

The approach

Authorize access with a conditional PostgreSQL update so only one concurrent request can claim a one-time note.

03 / UNDER THE HOOD

How it fits together.

  1. Next.js and Hono provide the interface and authenticated API; Prisma manages PostgreSQL records.
  2. Random share tokens are stored as SHA-256 digests, with bcrypt-hashed optional access keys.
  3. A transactional conditional update handles expiry, consumption, revocation and view counts.

04 / CAPABILITIES

What it does

  • Expiring and one-time share links
  • Optional access-key protection
  • Owner-controlled revocation
  • Database-backed concurrency controls

05 / ENGINEERING CHALLENGE

The important detail

Making access rules hold under concurrent requests and avoiding accidental consumption by previews or page prefetching.

06 / OUTCOME

What came out of it.

A deployed proof of concept with documented database and browser verification. Notes are not end-to-end encrypted.
